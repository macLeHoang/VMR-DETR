# Innovation Notes For This VMR-DETR Codebase

This note summarizes the main implementation ideas in this source base that extend a QD-DETR-style video moment retrieval baseline. The goal is to provide thesis-oriented notes that are grounded in the code, not to claim benchmark gains unless those results are documented elsewhere.

The project still follows the core DETR-style formulation: video and text features are encoded, decoder queries predict temporal spans, and the model is trained with matching-based supervision. The innovations below mainly improve temporal priors, multi-scale temporal reasoning, localization quality, positive assignment, and training stability.

## 1. Temporal Anchor Query Initialization

QD-DETR-style models usually learn decoder query embeddings from random initialization. This codebase adds a temporal prior for query references through `--query_init temporal_anchors`.

Instead of starting each decoder query without a temporal interpretation, the model initializes query reference points as normalized `(center, width)` temporal anchors. The default anchor pattern spreads centers across the video and cycles through several widths. A custom set of widths can be supplied with `--query_anchor_widths`, for example:

```bash
--query_init temporal_anchors --query_anchor_widths 0.08,0.22,0.48
```

Why it matters:

- The decoder starts from meaningful temporal hypotheses rather than only random query positions.
- Short, medium, and long moments can be represented from the first iteration.
- Dataset-specific moment durations can be injected as prior knowledge.

Code locations:

- `vmr_detr/modeling/model.py`: `init_temporal_queries`, query initialization in `VMRDETR`.
- `vmr_detr/config/options.py`: `--query_init`, `--query_anchor_widths`.
- `vmr_detr/scripts/estimate_query_anchor_widths.py`: estimates anchor widths from training JSONL windows.
- `vmr_detr/scripts/train.sh`: uses `--query_init temporal_anchors`.

## 2. Temporal Pyramid Memory

The codebase adds multi-scale video memory through `--use_temporal_pyramid`. Instead of passing only the original per-clip video sequence into the transformer, the model can append pooled temporal levels with configurable strides such as `1,2,4`.

The first level keeps the original temporal resolution. Additional levels are generated by downsampling video tokens either with masked average pooling or convolutional downsampling:

```bash
--use_temporal_pyramid \
--temporal_pyramid_downsample conv \
--temporal_pyramid_strides 1,2,4
```

Why it matters:

- Fine temporal tokens preserve boundary detail.
- Coarser temporal tokens provide broader context for long moments.
- Decoder cross-attention can reason over multiple temporal scales in one memory sequence.
- Masked pooling/convolution keeps padded clips from contaminating valid temporal tokens.

Code locations:

- `vmr_detr/modeling/model.py`: `_build_temporal_pyramid`, `_masked_temporal_pool`, `_masked_temporal_conv`.
- `vmr_detr/config/options.py`: `--use_temporal_pyramid`, `--temporal_pyramid_downsample`, `--temporal_pyramid_strides`.
- `vmr_detr/scripts/train.sh`: enables temporal pyramid with `conv` downsampling and strides `1,2,4`.

## 3. Optional Temporal Local Block

The model includes an optional masked residual temporal convolution block controlled by `--use_temporal_local`. This block applies local temporal filtering before transformer processing. It uses depthwise temporal convolution, pointwise expansion/projection, residual layer scales, and padding-aware masking.

Why it matters:

- Local motion/context patterns can be modeled before global transformer attention.
- Dilations allow a small block to cover different local temporal ranges.
- Mask renormalization avoids weakening boundary tokens or using padded positions as false context.
- Small residual scale initialization makes the block start as a mild perturbation.

The current `vmr_detr/scripts/train.sh` defines the temporal-local settings but leaves the enable flag empty, so this feature is available but not enabled by that script unless `--use_temporal_local` is passed.

Code locations:

- `vmr_detr/modeling/model.py`: `TemporalLocalBlock`, `_masked_depthwise_conv`.
- `vmr_detr/config/options.py`: `--use_temporal_local`, `--temporal_local_layers`, `--temporal_local_kernel_size`, `--temporal_local_dilations`, `--temporal_local_dropout`.
- `tests/test_task_aligned_matching.py`: shape, masking, dilation, and compatibility tests.

## 4. FDR Span Regression

The codebase extends span prediction with `--span_loss_type fdr`. FDR predicts residual start/end offset distributions around decoder reference spans. The decoder outputs logits over a symmetric non-uniform offset support that is dense around zero, then decodes the expected start/end offsets relative to the reference width.

Important details:

- The offset support is symmetric and controlled by `--fdr_reg_scale`.
- Offsets are relative to the current/reference temporal span width.
- A minimum reference width, `--fdr_min_ref_width`, prevents degenerate scaling.
- Decoder-layer FDR logits are accumulated and decoded against the initial reference.

Why it matters:

- The model predicts boundary corrections around a meaningful temporal reference.
- Dense bins around zero emphasize precise local refinement.
- Relative offsets adapt naturally to short and long moments.

Code locations:

- `vmr_detr/modeling/model.py`: `fdr_offset_support`, `fdr_logits_to_spans`, `_decode_fdr_cumulative_outputs`, FDR loss path in `SetCriterion`.
- `vmr_detr/config/options.py`: `--span_loss_type fdr`, `--fdr_num_bins`, `--fdr_reg_scale`, `--fdr_min_ref_width`.
- `vmr_detr/scripts/train.sh`: uses `span_loss_type=fdr`.
- `tests/test_task_aligned_matching.py`: FDR decoding, losses, empty-target behavior, and auxiliary-output tests.

## 5. Extra Boundary And Width Losses

In addition to the main span loss and temporal IoU/GIoU loss, this codebase includes optional auxiliary localization losses:

- `--span_xx_loss_coef`: supervises start/end boundary coordinates directly.
- `--width_loss_coef` with `--width_loss_type l1/log`: regularizes predicted moment width.

Why it matters:

- Boundary loss emphasizes start/end accuracy directly, which is useful when center-width errors hide asymmetric boundary mistakes.
- Width loss discourages over-wide or under-wide predictions.
- These losses complement FDR because FDR refines boundaries through residual distributions.

Code locations:

- `vmr_detr/modeling/model.py`: `SetCriterion` span and width loss branches.
- `vmr_detr/config/options.py`: `--span_xx_loss_coef`, `--width_loss_coef`, `--width_loss_type`.
- `vmr_detr/scripts/train.sh`: sets `span_xx_loss_coef=3.0`, `width_loss_type=log`, and `width_loss_coef=0.25`.

## 6. Task-Aligned And One-To-Many Matching

The repository supports matching alternatives beyond standard one-to-one Hungarian assignment.

Task-aligned matching (`--matching_type tal`) uses a TOOD-style alignment score:

```text
alignment = classification_score^alpha * temporal_iou^beta
```

It selects top-k queries per target, then resolves duplicate query assignments by keeping the best target. There is also an auxiliary one-to-many matcher used for richer auxiliary supervision.

Why it matters:

- Hungarian matching gives one positive query per target.
- Task-aligned or one-to-many assignment can expose more high-quality queries to positive supervision.
- Alignment combines classification confidence and temporal localization quality.

Code locations:

- `vmr_detr/modeling/matcher.py`: `TaskAlignedMatcher`, `OneToManyMatcher`, `build_matcher`, `build_one_to_many_matcher`.
- `vmr_detr/config/options.py`: `--matching_type`, `--tal_topk`, `--tal_alpha`, `--tal_beta`, `--aux_matching_type`, `--aux_one_to_many_k`.
- `tests/test_task_aligned_matching.py`: matching behavior and validation tests.

## 7. IoU-Aware Classification Labels: Quality And VFL

The codebase adds label losses that use localization quality rather than only hard foreground/background classification.

Two variants are implemented:

- `--label_loss_type quality`: Hungarian matches receive softened IoU-aware target quality. The target can ramp from a hard positive label toward an IoU-powered quality target.
- `--label_loss_type vfl`: Varifocal-style loss uses matched IoU as the positive target score and focal-style weighting for negatives.

Why it matters:

- The classification score becomes more aligned with localization quality.
- Higher confidence should correspond to better temporal overlap, improving ranking and post-processing.
- Warmup/ramp settings make quality supervision less abrupt early in training.

Code locations:

- `vmr_detr/modeling/model.py`: `_hungarian_quality_targets`, `_loss_labels_hungarian_quality`, `_loss_labels_vfl`.
- `vmr_detr/config/options.py`: `--label_loss_type`, `--quality_label_strength`, `--quality_label_iou_gamma`, `--quality_label_warmup_epoch`, `--quality_label_ramp_epoch`, `--vfl_alpha`, `--vfl_gamma`.
- `vmr_detr/scripts/train.sh`: currently uses `label_loss_type=vfl`.
- `tests/test_task_aligned_matching.py`: quality-label and VFL loss tests.

## 8. GO-LSD Self-Distillation Across Decoder Layers

GO-LSD is implemented as an auxiliary self-distillation loss for FDR span logits. When enabled, auxiliary decoder outputs learn from final-layer span logits after a start epoch.

The training script sets:

```bash
go_lsd_loss_coef=0.5
go_lsd_temperature=3.0
go_lsd_start_epoch=10
```

Why it matters:

- Earlier decoder layers receive a stronger training signal from the final decoder layer.
- The method encourages consistency across decoder depths.
- It is tied to FDR logits, so it distills distributional boundary refinement rather than only decoded coordinates.

Important constraints from option validation:

- GO-LSD requires `--span_loss_type fdr`.
- GO-LSD requires auxiliary decoder losses.
- It is not used for TVSum in the current validation logic.
- Setting `--go_lsd_loss_coef 0` disables it.

Code locations:

- `vmr_detr/modeling/model.py`: `_loss_go_lsd`, `_get_global_optimal_indices`, criterion forward path.
- `vmr_detr/config/options.py`: `--go_lsd_loss_coef`, `--go_lsd_temperature`, `--go_lsd_start_epoch`.
- `tests/test_task_aligned_matching.py`: GO-LSD loss and validation tests.

## 9. Contrastive Query-Text Alignment

The model can add an NCE-style contrastive alignment loss between decoder query embeddings and text memory with `--contrastive_align_loss`.

The code uses matched query-span assignments to decide which decoder queries should align with text tokens. It also supports a start epoch and decay schedule:

```bash
--contrastive_align_loss \
--contrastive_align_loss_coef 0.3 \
--contrastive_start_epoch 0 \
--contrastive_decay_epoch 30 \
--contrastive_decay_coef 0.1
```

Why it matters:

- Decoder queries are encouraged to remain semantically tied to the input text.
- The loss adds cross-modal supervision beyond span regression and saliency ranking.
- Decay lets the auxiliary objective become weaker after a chosen training stage.

Code locations:

- `vmr_detr/modeling/model.py`: `loss_contrastive_align`, `loss_contrastive_align_vid_txt`.
- `vmr_detr/config/options.py`: `--contrastive_align_loss`, `--contrastive_align_loss_coef`, `--contrastive_start_epoch`, `--contrastive_decay_epoch`, `--contrastive_decay_coef`.
- `vmr_detr/scripts/train.sh`: enables contrastive alignment.

## 10. EMA Scheduling And EMA Checkpointing

The training loop includes model exponential moving average (EMA) support plus a scheduled EMA decay. Instead of using only a fixed decay from the first update, the code can start EMA after a chosen epoch and warm the decay from a smaller value to the target value.

The default script configures:

```bash
--ema_decay 0.999 \
--ema_scheduler \
--ema_start_epoch 1 \
--ema_start_decay 0.995 \
--ema_warmup_updates 2000 \
--ema_update_every 1 \
--ema_schedule cosine
```

Why it matters:

- EMA evaluation can improve stability compared with raw online weights.
- Scheduled decay avoids overly stale EMA weights early in training.
- EMA state and scheduler state are saved and restored in checkpoints.

Code locations:

- `vmr_detr/cli/train_utils.py`: `ModelEMA`, `EMAScheduler`.
- `vmr_detr/cli/train.py`: EMA setup, update, evaluation, save, and restore integration.
- `vmr_detr/config/options.py`: EMA command-line options.
- `tests/test_ema_scheduler.py`: EMA schedule, update interval, state dict, and reset tests.

## Default Experiment Recipe

The current `vmr_detr/scripts/train.sh` combines several of these ideas in one Charades-STA-style configuration:

- Temporal anchor queries with `query_anchor_widths=0.08,0.22,0.48`.
- FDR span regression with `fdr_num_bins=32`.
- Temporal pyramid memory using convolutional downsampling and strides `1,2,4`.
- Boundary and width regularization through `span_xx_loss_coef` and `width_loss_coef`.
- VFL label loss for IoU-aware confidence prediction.
- GO-LSD configured with coefficient `0.5` and start epoch `10`.
- Contrastive query-text alignment enabled.
- EMA scheduling with cosine warmup toward decay `0.999`.

This script is a useful source for describing the intended combined method, but it also contains machine-specific dataset paths. For reproduction notes, separate the method configuration from local path settings.

## Notes For Thesis Writing

Use careful wording such as:

- "The source base extends a QD-DETR-style architecture with temporal-anchor query initialization and multi-scale temporal memory."
- "The temporal pyramid introduces coarse video tokens while preserving the original fine-resolution tokens for boundary-sensitive prediction."
- "FDR reformulates span prediction as reference-relative boundary offset distributions, enabling fine residual boundary refinement."
- "IoU-aware label losses align classification confidence with localization quality, which is important for ranking predicted moments."
- "GO-LSD and EMA scheduling are training-stability components rather than architectural changes."

Avoid unsupported claims such as "state-of-the-art" or "improves accuracy by X" unless you add experimental evidence and citations.
